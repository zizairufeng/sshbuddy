# SSHBuddy 1.3.6 二次代码审查

- 日期：2026-10-23
- 审查者：小w（对 1.3.5/1.3.6 这轮改动的独立复核）
- 审查范围：`app/src/main/java` 全部 Kotlin/Java、`proguard-rules.pro`、`build.gradle.kts`、
  `AndroidManifest.xml`、`release-mapping/mapping-1.3.6.txt`、`dist/SSHBuddy-1.3.6-release.apk` 产物内容

## 结论

**这轮改动整体优于 1.2.1，其中三处修的是我原实现的真 bug，不是风格差异。**
但仍有 4 个必须处理的问题，集中在「加密存储的失败路径」和「RDP 证书校验缺位」。

## 一、确实修对了的地方

### 1. 键盘映射（我原来是错的）

原实现把 Android `KeyEvent.keyCode` 直接传给 `LibFreeRDP.sendKey`，而 native 侧
（`android_freerdp.c:1051`）是：

```c
scancode = GetVirtualScanCodeFromVirtualKeyCode(keycode, 4);
```

它期待的是 **Windows VK**。`winpr/libwinpr/input/scancode.c:1042` 取 `vkcode & 0xFF` 查表，
于是 Android 的 `KEYCODE_ENTER(66)` 会被当成 `VK 0x42`（字母 B），`KEYCODE_DEL(67)` 变成 C。
**回车打不出回车、字母错位**，这是原版一直存在的隐性 bug。

新增 `RdpKeyMapper` 显式做 Android → VK 映射；扩展键用 `or 0x100`，与 winpr 的
`KBDEXT(0x100)` 语义一致（`scancode.c:1049-1050` 走 `map->kbdext` 扩展表），
方向键 / Home / End / Del / 小键盘回车都能正确置上 `KBD_FLAGS_EXTENDED`。这块完全正确。

### 2. 断开时序（我原实现会回收掉新连接的位图）

原 `close()` 在清理线程里 `screenBitmap?.recycle()` 读的是**字段**，而 `start()` 会先建新位图。
快速重连时旧清理线程回来把新位图 recycle 掉 → 黑屏。现在先 `also { screenBitmap = null }`
把引用摘走，再交给清理线程回收，顺序是对的。

per-instance 的 `closeLatches`（按 native 实例 id 索引）也比原来单闩锁严谨：
旧实例的 `OnDisconnected` 不会提前放行新实例的释放流程。超时不 `freeInstance`、
宁可泄漏也不 use-after-free 的取舍也是对的。

### 3. 安全基线（原来等于没有）

- `SecureStore`：Keystore + AES-256-GCM，12 字节随机 IV + 128bit tag，格式带 `enc1:` 前缀，
  旧明文自动迁移，写法规范。
- `KnownHostsStore`：从 `StrictHostKeyChecking=no` 改成 TOFU +
  `StrictHostKeyChecking=yes`，`check()` 里比对 SHA-256 指纹，`add()` 用 Base64 解码后的
  raw blob 算指纹（与 `check()` 的入参对齐）——这一步很多人会写错，这里处理对了。
- `allowBackup=false`、`RdpActivity exported=false`、权限没膨胀，清单很干净。

### 4. 体积与合规

- R8 + `useLegacyPackaging`：22.6MB → 6.2MB。实测产物内容完整：
  `lib/arm64-v8a/` 下 9 个 so 全在（raw 11,076,616 B），`classes.dex` 2.96MB，没有瘦身过头。
- R8 映射实测：`LibFreeRDP`、`LibFreeRDP$Listener` 类名均未被混淆
  （`release-mapping/mapping-1.3.6.txt` 里 `-> ...LibFreeRDP` 同名），JNI 的
  `FindClass`/`GetStaticMethodID` 不会失效。
- Termux 的许可证结论（terminal-emulator / terminal-view 走 Apache-2.0 例外，而非主体 GPLv3）
  是查过 `LICENSE.md` 的，还留了 commit hash、附了 Apache-2.0 全文。这个我原来会想当然按 GPLv3 处理。

### 5. 参数合法性（逐条核对 FreeRDP 3.32.2 源码）

`/kbd:unicode`（`cmdline.c:3088` 的 `option_starts_with("unicode")`）、
`/auto-reconnect`、`/auto-reconnect-max-retries`、`/bpp:32`、`/client-hostname`、
`/network:auto`、`/dynamic-resolution` 全部存在于 `client/common/cmdline.h` 的
`global_cmd_args[]`，值也合法。`/sec:auto` 的历史坑没有再犯（auto 时不传 `/sec`）。

## 二、必须修

### P0：Keystore 失效会导致主机列表被静默覆盖丢失

链路（`SshConfig.kt:105-128`）：

1. `SecureStore.decrypt()` 失败 → 返回 `""`（`SecureStore.kt:70-73`）
2. `loadHosts()` 见 `json.isBlank()` → `return emptyList()`（`:111`），**不报警、不备份**
3. 用户看到列表空了，新建一台 → `upsertHost()` → `loadHosts()` 仍是空 → `saveHosts()`
   **把整个 `hosts.v2` 覆盖成一条**

触发条件真实存在：换机/厂商搬家工具迁移数据（Keystore 密钥不随 SharedPreferences 走）、
清除数据后从备份还原、个别 ROM 的 Keystore 损坏。届时 SSH 密码、私钥、RDP 凭据全丢。

建议：`decrypt` 失败时不要返回 `""`，改为返回 `null` 与「数据存在但解不开」区分开；
`loadHosts` 遇到这种情况**抛/带出错误标记**，UI 明确提示「本机加密密钥已失效，原配置无法解密」，
并在用户确认前**禁止写入**（或先把原密文另存 `hosts.v2.broken-<ts>`）。

### P0：`encrypt` 静默降级明文

`SecureStore.kt:50-53`：加密失败只打一行 `Log.e`，然后**把明文写盘**，用户无感。
一旦发生，密码连 AES 这层都没了，与 1.2.1 的明文存储等价，但用户以为已经加密。

建议：失败向上抛，保存流程提示「本机安全存储不可用，本次不会保存密码」，
或者退化为「只存非敏感字段」。安全能力降级必须让用户知情。

### P1：RDP 证书无条件放行，与 SSH 侧刚做的 TOFU 明显不一致

`RdpSession.kt` 的 `buildArgs()` 里固定 `/cert:ignore`，注释也承认了。
结果：SSH 做了中间人防护，RDP 侧仍可被任意伪造证书接管（传输的密码直接暴露）。

`LibFreeRDP` + `RdpSession` 里的 `onVerifyCertificate` / `onVerifyChangedCertificate`
回调是完整的（指纹、changed 标志都有），只是被 `/cert:ignore` 短路了，从未触发。

建议：把 `/cert:ignore` 换成 `/cert:tofu`（FreeRDP 自带，首次记录、变化即拒），
或去掉该参数、用回调按主机名存指纹（可与 `KnownHostsStore` 共用一个存储）。
工作量很小，收益是把两条协议的安全水位拉平。

### P1：`promptYesNo` 恒 true 与 TOFU 策略冲突

`SshSession.kt:94`：`promptYesNo() = true`。当前 `check()` 对未知主机返回 `OK`（自己记录），
所以走不到这条路径，属于死代码；但一旦将来 `check()` 改成返回 `NOT_INCLUDED`（比如加人工确认），
这里会**自动替用户点"同意"**，把刚做的防护又绕过去。建议直接返回 `false`。

## 三、建议（不阻塞）

1. **双层重连未收口**：`RdpSession` 传了 `/auto-reconnect-max-retries:5`，`RdpActivity`
   又有 `scheduleReconnect()`（`:302`）。native 重连期间没有任何回调，UI 会停在冻结画面；
   建议订阅 FreeRDP 的重连状态事件，至少在界面上显示"正在重连 n/5"。
2. **`KnownHostsStore.mismatch` 用 `ThreadLocal`**：目前 `clearMismatch()` 与 `lastMismatch`
   都在 `withContext(Dispatchers.IO)` 的同一线程上，成立；但这依赖"JSch 的 check 与读取同线程"
   这个隐含前提，属于脆设计。改成 `ConcurrentHashMap<String, String>`（键 host）更稳。
3. **`useLegacyPackaging = true`**：安装时解压 so，安装体积会临时翻倍、首次启动略慢。
   自用可接受，但值得在 README 里写一句。
4. **零测试**：16000 行代码没有一行单测。`SecureStore` 的格式兼容（明文/密文/损坏）、
   `KnownHostsStore.fingerprint` 的一致性、`RdpKeyMapper` 的映射表都是纯函数，单测成本极低、收益高。
5. **`upsertHost`/`deleteHost` 是读-改-写**，非原子。单进程 UI 下问题不大，多标签并发保存时有覆盖窗口。
